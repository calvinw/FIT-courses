Fashion Boutique Database: Starter SQL Scripts

Fall 26

Author

Calvin Williamson, Science and Math

These scripts build a small database for a fashion boutique with three locations. It has three tables: stores, products, and inventory. inventory records how many of each product each store has on hand, so it connects the other two tables. Copy each block (use the copy button in its top right corner) and paste it into the Dolt online SQL editor, then run it. Run the blocks in order: inventory refers to the other two tables, so they have to exist first.

1. Create the stores table

Each store gets a unique store_id, which is the primary key.

CREATE TABLE stores (
  store_id int NOT NULL,
  store_name varchar(255),
  city varchar(255),
  opened_date date,
  PRIMARY KEY (store_id)
);

3. Create the products table

Each item the boutique sells gets a unique product_id, which is the primary key. A style that comes in two colors is two separate products. cost is what the boutique pays the supplier and price is what the customer pays.

CREATE TABLE products (
  product_id int NOT NULL,
  name varchar(255),
  category varchar(255),
  color varchar(255),
  cost decimal(10,2),
  price decimal(10,2),
  PRIMARY KEY (product_id)
);

5. Create the inventory table

Each row says how many of one product one store has on hand. The primary key is the pair (store_id, product_id): a store can carry many products and a product can be stocked in many stores, but each store and product pair appears only once. Both columns are foreign keys. store_id points back to the stores table and product_id points back to the products table. reorder_level is the quantity at which the store should order more.

CREATE TABLE inventory (
  store_id int NOT NULL,
  product_id int NOT NULL,
  quantity int,
  reorder_level int,
  PRIMARY KEY (store_id, product_id),
  FOREIGN KEY (store_id) REFERENCES stores (store_id),
  FOREIGN KEY (product_id) REFERENCES products (product_id)
);
